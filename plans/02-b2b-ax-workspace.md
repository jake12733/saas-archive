# B2B 리드·CS 자동화(AX) 워크스페이스

> 고객 문의 폼·이메일을 웹훅으로 수집해 AI가 자동 분류·요약·답변 초안을 만들고 슬랙으로 알림을 보내주는 팀용 B2B SaaS

## 기본 정보
- **SaaS 유형**: B2B, Vertical, AI-native
- **진행 상태**: 기획중
- **핵심 타깃 고객**: 소규모 B2B 스타트업, 마케팅/AX 에이전시 운영팀
- **수익 모델**: 워크스페이스 좌석(Seat) + 월 자동화 실행 건수 티어 과금
- **기술 스택**: Next.js, TypeScript, PostgreSQL, Prisma, RBAC, Webhook, Slack API
- **라이브 데모**: (예정)
- **GitHub**: (예정)

## 1. 문제 정의 & 타깃 고객 (Why)
- 소규모 팀에 매일 들어오는 제휴·견적·CS 문의를 담당자가 수동으로 분류하고 복붙 답변하느라 리드 응답 속도가 늦어짐.
- 누가 어떤 문의에 답했는지 추적이 안 되어 영업 기회가 누락됨.

## 2. 핵심 기능 & 사용자 흐름 (What / MVP Scope)
- **핵심 기능 1**: 워크스페이스별 전용 Webhook URL 및 임베드 문의 폼 발급
- **핵심 기능 2**: 문의 접수 시 AI가 카테고리(견적/기술/제휴)·긴급도 분류 + 답변 초안 생성
- **핵심 기능 3**: 슬랙 알림 발송 및 자동화 실행 로그(성공/실패/재시도) 대시보드

## 3. SaaS 비즈니스 구조 (과금 · 권한 · 멀티테넌시)
- 멀티테넌시: 모든 업무 테이블에 `workspace_id`를 두고 미들웨어/쿼리 레벨에서 엄격히 격리
- 권한(RBAC): Owner(결제·멤버 초대), Admin(자동화 규칙 설정), Member(문의 확인·답변)

## 4. 시스템 아키텍처 & DB / API 설계
- 주요 테이블: `workspaces`, `memberships`, `inbound_tickets`, `automation_rules`, `execution_logs`
- 비동기 흐름: Webhook 수신 → 즉시 202 응답 & DB 저장 → 백그라운드 워커가 LLM 분류 및 Slack 발송 → 결과 로그 기록

## 5. 기술적 의사결정 & 트레이드오프 (ADR)
- **[선택 1]** 테넌트별 DB 분리 대신 단일 DB + `workspace_id` 컬럼 방식 선택
  - 이유: 초기 운영 비용과 스키마 마이그레이션 복잡도를 줄이면서 B2B 멀티테넌시의 핵심인 접근 제어를 확실히 구현하기 위해.
